# 核心理念：agent 时代的 DSH 插件脚手架

> 一句话：**把 DSH 插件开发里那些确定、重复、容易忘的步骤，做成创造模式里稳定又快的工具；把需要判断的部分留给技能和对话。**

这个文档是本项目的设计依据。改代码之前先读它，尤其是第 2 节——**创造模式的工具是这个插件的地基**。

## 1. 目标：一条完整的插件开发周期

一个插件从想法到发版，是六段：

| 阶段 | 这一段真正要做的事 | 本项目现在的能力 | 还缺什么 |
|---|---|---|---|
| **构思** | 想清楚边界：要不要工具 / 技能 / 客户端一半 / 只给一个预设 | 场景分析（`scenario-driven-product-design`，缺失时用自带的 `references/conception.md`）+ 形态判定表 + 五行决策记录 | 不做完整产品文档；形态仍由用户拍 |
| **项目启动** | 骨架、清单、bundle patch、locale、图标、README | `dsh_plugin_new` + 标准模板 + `dsh_plugin_check` | 模板只有最小可跑集，没有 lint / 构建 / 单测脚手架 |
| **规范化开发与检查** | 结构别走样；不许把开发中的包装进当前环境 | 项目声明式规则（断链 / locale 对齐 / 分层依赖方向 / console）+ `dsh_plugin_check`（结构 12 项）+ 安装守卫 | 不做 lint；契约漂移的「生成」那半还没有 |
| **功能测试** | 起一个不干扰的实例，打契约，对数据 | `dsh_sandbox`（create/start/http/seed/stop）+ 技能 | 无 |
| **集成测试** | 装进真宿主、客户端注册、人眼看 | 沙盒 + CDP（截图 / 断言 / 真实点击与输入 / console error）+ Inspect + 「未验证要写出来」的纪律 | 不覆盖多窗口、拖拽、输入法；视觉判断仍需人 |
| **发版** | 版本、构建、门禁、包面、装真实 profile、回滚、对账 | 就绪检查（真实包面 + `engines.dsh` 兼容性）+ 打包 + **沙盒演练**（装 tarball、读回组合、给回滚命令） | 不发布（`npm publish` 是人的决定）；semver 是子集；不验 registry 权限 |

诚实地说：**六段里五段已经成形，「构思」这一段刚刚补上流程但还很薄。** 「需求 → 插件形态」的判定现在有清单和形态表兜着（见 `skills/dsh-plugin-new/references/conception.md`），但它是一段**对话流程**，不是机械检查——形态选错，后面的工具全都在为错误的形状服务。

> 这张表讲能力。**哪个工具实现了哪条能力、参数是什么、边界在哪**，见 [`TOOLS.md`](TOOLS.md)；方案的格式见 [`SCHEMES.md`](SCHEMES.md)；发版步骤见 [`RELEASE.md`](RELEASE.md)。README 只讲能力，工具清单不进 README。

## 2. 第一原则：创造模式的工具是地基

这个插件**不自己实现插件开发**，它只补创造模式（`cordis` 预设）缺的那几块。所以：

**改任何东西之前，先看清地基上已经有什么**，别猜、别重造：

- 静态：`dsh --profile <p> --dump-config` 看组合后的插件树；
- 运行时：`cordis_inspect_list` / `cordis_inspect_query` 看服务方法、事件模式、工具 schema、slot 树、主题 token。

出厂 32 个插件（本包只加了最后 2 个）：

| 分组 | 插件 | 对我们的含义 |
|---|---|---|
| 人格与上下文 | `persona` `agent-instructions` `time-context` | 提示词层已有人管，别再插一段 |
| 文件与命令 | `tool-fs` `tool-fs-search` `tool-bash` `tool-pwsh` `tool-jobs` | 读写文件、跑命令不用我们重造；我们只产出「该跑什么」 |
| 计划与目标 | `command-goal` `tool-goal` `planning` `plan-mode` `tool-todo` | 长任务的计划能力现成，脚手架不该自带计划器 |
| 压缩与结果 | `compaction` `compaction-basic` `command-compact` `tool-result-pruner` | 输出要短；别把大块文本塞回上下文 |
| 委派与多智能体 | `delegation` `tool-subagent` `tool-subagent-control` `tool-subagent-fork` `workflow-ptc` `tool-workflow` | 批量改造/审计该用 workflow，而不是在本包里写并发 |
| 交互 | `tool-ask-user` `present` | 需要用户拍板就问，不要替用户决定 |
| 网络 | `tool-web` | 查资料用现成的 |
| DSH 自身 | `tool-cordis`（Inspect） `tool-plugin-manager` `tool-plugin-market` | **装/卸/启用是 `plugin_manager` 的事**；运行时真相从 Inspect 来，不从源码猜 |
| 技能 | `skill-filesystem` `tool-skill` | 判断类知识写成技能，不写进工具描述 |
| 本包 | `creator-tools` `creator-skills` | 只放前九组没有的东西 |

由此得到四条硬约束：

1. **不重造 `plugin_manager`**：我们只做它不做的事——检查一个包结构对不对、拦住不该装的安装。
2. **不猜运行时**：slot 树、工具 schema、服务签名一律 Inspect 或 `--dump-config`，不读源码推断。
3. **判断不进工具**：工具描述里不写「你应该先…」，那是技能的事。
4. **地基变了要跟**：预设整段覆写在 `cordis.patch.yml` 里，DSH 升级后要用 `scripts/check-patch.mjs` 重新对账。

## 3. 四条设计原则

**① 确定性的交给代码，判断的交给技能。**
填模板、算端口、起实例、比标记——都是确定性的，写成引擎；问字段、选沙盒、判「这算不算验过」——是判断，写进技能。混在一起就是不可靠的模板生成器。

**①′ 结构写成数据，代码只写必须算的部分。**
「模板 + 命令 + 配置」不是一次性的技巧，而是这个项目的基本能力：一个方案 = `recipe.json`（变量、文件映射、条件、规则）+ 模板目录 + 少量 derive 钩子；引擎不认识插件，只认变量和文件。**加一个新方案 = 加一个目录，不是加一个生成器**。规范也随之变成数据：生成完立刻按方案自己的规则验一遍（占位符、打包白名单、清单字段、frontmatter）。细节见 [`SCHEMES.md`](SCHEMES.md)。

**② 能拒绝就不要只写建议。**
规则是建议，guard 是拒绝。「开发中的插件不许装进当前环境」如果只写在技能里，压力大时模型会跳过；做成 `ctx.tools.guard()`，它跳不过去。同理：沙盒的归属标记、`stop` 的 pid 校验。

**③ 复用优先，重建是例外。**
沙盒里的模型凭据、pnpm 安装、profile 版本都是「攒出来的资产」。默认复用；要干净环境就**新建一个沙盒**，不要删正在用的那个。

**④ 验证到哪说到哪。**
没验到的写「未验证」，不写「应该没问题」；不为了出图去伪造页面、找 token、自建渲染器。这条来自真实事故——假证据比没有更糟。

## 4. 怎么扩展这个项目

新增一项能力时，按这个顺序：

1. **先看地基**：`--dump-config` 里有没有现成的插件？Inspect 里有没有现成的服务/事件？（第 2 节）
2. **定性**：这件事是确定性的（→ 引擎 + 工具），还是判断（→ 技能），还是两者都要（→ 分开写）。
3. **先想能不能做成方案**：如果它产出的是「一组有固定结构的文件」，那就写一个 scheme（`recipe.json` + 模板 + 规则），而不是再写一个生成器。见 [`SCHEMES.md`](SCHEMES.md)。
4. **写引擎**：`lib/*.js`，只用 Node 内置模块——预设行从 profile 解析导入，`@deepseek-ai/*` 在这里**不可用**。
5. **写两个前门**：工具（agent 用）+ CLI（人和脚本用），都调同一个引擎。
6. **写回归**：`scripts/try-*.mjs`，能不开真宿主就不开（用假启动器 / 桩上下文）。
7. **同步文档**：README 只写**能力**（不写工具清单），工具的参数/动作/边界写进 [`TOOLS.md`](TOOLS.md)，方案格式写进 [`SCHEMES.md`](SCHEMES.md)，能力表更新到这个文件；`locale/{en,zh}.json` 的描述与相关技能段落也要跟着改。

## 5. 边界（不做什么）

- **不碰桌面端**：不启动它的二进制、不占它的端口（实测 `3081`、`52332`）、不按进程名批量杀进程。
- **不替用户做决定**：装到当前环境、删沙盒、复制模型凭据，都要用户点头。
- **不做权限边界**：guard 是防手滑的刹车，不是安全沙箱；标记能被手改，端口能被抢——我们只保证「不会悄悄发生」。
- **不吞掉失败**：检查器把每一项都报出来，而不是遇到第一个错误就抛异常。
